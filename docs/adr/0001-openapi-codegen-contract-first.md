# OpenAPI — источник истины, серверный код генерируется oapi-codegen

Спека `backend/api/openapi.yaml` пишется первой, из неё `oapi-codegen` (`std-http-server` + `strict-server`) генерирует модели и серверный интерфейс в `internal/api/api.gen.go`, файл коммитится, запуск через `make generate`. Хендлеры реализуют сгенерированный интерфейс, а не `net/http` вручную. Так спека не может разойтись с кодом, а типы фронта (`openapi-typescript`) строятся из того же файла.

## Considered Options

- **Хендлеры руками + контрактные тесты на `kin-openapi`.** Больше контроля и ближе к «ядро пишет владелец», но дрейф ловится только тестами, а не компилятором. Отклонено: подход «спека → код» выбран осознанно как практика контракт-первого дизайна.

## Consequences

- Спека остаётся на OpenAPI 3.0.3: `oapi-codegen` не поддерживает 3.1 полноценно.
- `operationId` и имена схем становятся именами Go-методов и типов, поэтому задаются явно.
- Токен (`bearerAuth`) проверяет вручную написанный middleware: генератор его не проверяет.
- Любое изменение API начинается с правки спеки и `make generate`; правка `api.gen.go` руками запрещена.
