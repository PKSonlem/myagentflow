# T2: Хуки Claude Code

**Цель:** реальные сессии Claude Code шлют события на локальный сервер.

## Кто что пишет
- Владелец: вся настройка и проверка. Тикет небольшой, но это первый контакт с реальным форматом.
- Агент: только отвечает на вопросы и ревьюит конфиг.

## Контекст
- Документация Claude Code, раздел hooks: тип `http`, поля `url`, `headers`, `allowedEnvVars`, `timeout`, `matcher`.
- T1 должен работать.

## Что сделать
1. В `~/.claude/settings.json` добавить http-хуки на события: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `Stop`, `SessionEnd`. URL `http://127.0.0.1:<port>/api/v1/hooks/claude` (префикс `/api/v1` из `servers.url` спеки, см. T1).
2. Токен передать через `headers` и `allowedEnvVars`, значение из переменной окружения, не в файле.
3. Короткий `timeout` (секунды): хук не должен тормозить агента.
4. Выполнить живую сессию и посмотреть сырые payload в логах/БД. Записать расхождения с ожидаемым форматом в `docs/notes/hooks-reality.md` (какие поля реально приходят, приходит ли текст промпта в `UserPromptSubmit` для `task_text`). Отдельно проверить: срабатывает ли `Stop` после каждого ответа или только в конце сессии, что приходит при `--resume`, присылает ли Claude Code повторы http-хука, поддерживает ли `SessionStart` http-хуки (см. «Риски из T1»), приходят ли `cwd` и `tool_use_id` во всех событиях, бывает ли `\u0000` в payload (сервер отвечает на него 400).
5. Остановить сервер и убедиться, что Claude Code продолжает работать без зависания.

## Риски из T1
- **`SessionStart` может не поддерживать http-хуки** (по документации, из сводки, не проверено; открытый вопрос T0). В T1 Run переоткрывается только событием `SessionStart`, а закрывается `SessionEnd`. Если `SessionStart` по http не приходит, возобновлённая сессия (`--resume`) шлёт события в уже `finished` Run и он остаётся `finished`, хотя сессия идёт: UI покажет её завершённой. Проверить в этом тикете: приходит ли `SessionStart` по http, что приходит при `--resume`.
- Если подтвердится, правило нужно менять (возможное решение: любое событие на `finished` Run переводит его обратно в `running`, `SessionStart` для этого не нужен). Это правка `UpsertRun` в `queries/runs.sql` и тест в `ingest/service_test.go`, а в `feature.md` и `GLOSSARY.md` надо поправить описание Run. Не менять заранее, пока нет реального поведения.

## Критерии приёмки
- После короткой сессии в БД есть `run` и события в правильном порядке.
- Остановка сервера не ломает и не подвешивает сессию.
- `hooks-reality.md` содержит реальные примеры payload (без секретов).

## Вне тикета
`PermissionRequest` (это спайк перед F02), подтверждения.
