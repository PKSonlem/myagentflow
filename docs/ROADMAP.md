# Agent Control Panel: ROADMAP

Исходная идея: `agent-control-panel.md` (вне репозитория). Здесь только принятые решения и порядок работ.

## Цель и правила

- Учебный проект: из Go backend в AI Engineer. Фронтенд (`web/`) целиком пишет агент, TypeScript/React не изучаем.
- **Бэкенд не вайбкодим.** Ядро и всё новое в `backend/` пишет владелец. Агент пишет там только рутину (docker-compose, конфиги, boilerplate), ревьюит и объясняет. Готовые решения агент не отдаёт, пока владелец не попробовал сам.
- **Фронтенд отдан агенту.** Владелец почти не читает код `web/`. Гарантии качества: контракт OpenAPI, `zod` на границе, `tsc --noEmit` и линтер, живая проверка в браузере по критериям приёмки.
- Работа идёт **фичами**. Фича = полностью рабочий результат, состоит из тикетов (API, фронт и т.д.). Один тикет = одна сессия, примерно 3-5 файлов.
- Детально расписана только текущая фича, остальные остаются строкой ниже.

## Принятые решения

| Область | Решение |
|---|---|
| Бэкенд | Go 1.27, stdlib `net/http`, pgx + sqlc, goose, slog |
| Фронт | React + TypeScript, монорепо (`backend/`, `web/`, `docs/`) |
| Контракт | OpenAPI 3.0.3 как источник истины, серверный код генерирует `oapi-codegen`, типы фронта `openapi-typescript`, `zod` на границе ([ADR-0001](adr/0001-openapi-codegen-contract-first.md)) |
| Источник событий | Только Claude Code, через http-хуки напрямую на сервер |
| Адаптер | Модуль `claudecode` принимает нативный payload хука. Ключ идемпотентности `(session_id, hook_event_name, tool_use_id)`, `seq` назначает сервер |
| Хуки F01 | `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `Stop`, `SessionEnd`: отправить и не ждать |
| Хук approvals (F02) | Только `PermissionRequest`. При таймауте штатный диалог. Перед F02 спайк: что делает Claude Code при упавшем сервере |
| Авторизация | Статический токен из env на всех эндпоинтах, сравнение `crypto/subtle`. UI на localhost без логина |
| Секреты | В БД как есть. Маскировать перед Telegram и в логах |
| Тесты | Реальный Postgres (testcontainers). Тест сначала для конкурентности и состояний |
| Партиционирование | Не в F01. Отдельная фича с замерами `EXPLAIN ANALYZE`. Первичный ключ `events` включает `ts` |

## Фичи

| # | Фича | Статус |
|---|---|---|
| F01 | Observe: запуски Claude Code видны на странице | в работе, `features/F01-observe/` |
| F02 | Approvals: подтверждение через Telegram (до неё спайк по хукам) | идея |
| F03 | Политики: «Always allow» с телефона | идея |
| F04 | Детектор повторов на `pg_trgm`, карточки предложений | идея |
| F05 | Агент-генератор черновиков скиллов (свой agent loop на Go, прямой Anthropic API) | идея |

## Отложено (вернёмся при условии)

| Ветка | Когда возвращаемся |
|---|---|
| Детектор: текст или ещё последовательности инструментов, пороги | перед F04, после недели реальных данных |
| Эмбеддинги и pgvector | после MVP на `pg_trgm` |
| Доставка скиллов на машину агентов | после F04 |
| Obsidian-экспорт | после F02 |
| Токены и стоимость из `transcript.jsonl` | после спайка по транскрипту |
| Статус запуска `abandoned` (воркер) | после F01, когда появятся оборванные сессии |
| Партиционирование и ретеншн | отдельная фича по замерам |
| Тикеты для нескольких репо | когда появится второй репозиторий с агентами |
| SSE, VPS, HTTPS, демо, ClickHouse | не планируем до F03 |
