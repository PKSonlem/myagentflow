# MyAgentFlow

Панель наблюдения за Claude Code: что агент делал в каждой сессии, в каком порядке и чем всё закончилось.

> **Проект в разработке.** Идея и архитектура определены, первая версия собирается. Готового продукта пока нет, ниже написано, что уже есть и что будет.

## Зачем это

Claude Code работает автономно: читает файлы, запускает команды, правит код. После длинной сессии сложно вспомнить, что именно произошло. Терминал прокручивается, история теряется, а сессий много.

MyAgentFlow собирает события Claude Code в одном месте и показывает их как понятную хронологию: какие сессии были, какие инструменты вызывались, где случились ошибки.

Что получится в итоге:

- **Список запусков.** Каждая сессия Claude Code это один запуск со статусом, рабочей папкой, началом, концом и длительностью.
- **Таймлайн событий.** Внутри запуска видно каждый шаг агента по порядку: вызов инструмента, его результат, ошибки. Любое событие раскрывается до полного содержимого.
- **Дальше (идеи).** Подтверждение опасных действий с телефона через Telegram, правила «всегда разрешать», поиск повторяющихся действий и подсказки, какие из них стоит оформить как навык.

## Как это работает

```text
┌─────────────┐  HTTP-хуки   ┌──────────────┐          ┌──────────┐
│ Claude Code │ ───────────► │  Go-сервер   │ ───────► │ Postgres │
└─────────────┘              └──────┬───────┘          └──────────┘
                                    │ REST API
                             ┌──────▼───────┐
                             │ React + TS   │
                             │ список и     │
                             │ таймлайн     │
                             └──────────────┘
```

У Claude Code есть [хуки](https://docs.claude.com/en/docs/claude-code/hooks): настраиваемые обработчики, которые срабатывают на события (начало сессии, вызов инструмента, ошибка, завершение). Хук может отправить событие по HTTP на ваш сервер. MyAgentFlow принимает эти события, сохраняет их и отдаёт интерфейсу.

Основные понятия:

- **Run** это один запуск агента, соответствует одной сессии Claude Code. Пока сессия идёт, он в статусе `running`, после её завершения `finished`. Возобновлённая сессия снова открывает тот же Run.
- **Event** это одна запись хронологии, соответствует одному вызову хука. События внутри Run упорядочены по номеру, который назначает сервер.

Словарь терминов лежит в [`GLOSSARY.md`](GLOSSARY.md).

## Как я это делаю

Это учебный проект: я Go-разработчик и иду к AI Engineering, параллельно осваивая TypeScript и React. Поэтому:

- **Контракт первым.** Сначала я описываю API в спецификации OpenAPI, и только потом пишу код. Из спецификации генерируются серверный интерфейс на Go и типы для фронтенда, поэтому код и контракт не расходятся.
- **Тесты на настоящей БД.** Для кода, который работает с Postgres, тесты запускаются на реальном Postgres в контейнере, а не на моках. Особенно это важно для конкурентности и повторной отправки событий.
- **Минимум зависимостей.** Сервер написан на стандартном `net/http` с `slog`, работа с БД через `pgx` и `sqlc`, миграции через `goose`.
- **Идемпотентность.** Claude Code может прислать одно и то же событие повторно. Сервер распознаёт повторы по ключу и не создаёт дубликатов.
- **Ядро пишу сам.** Ассистент помогает рутиной, ревью и объяснениями, но не пишет за меня логику.
- **Работа фичами.** Каждая фича доводится до полностью рабочего результата, прежде чем начинается следующая.

## Установка и запуск

### Что понадобится

- Go 1.26 или новее
- Docker с Docker Compose
- Node.js (для проверки спецификации и генерации типов фронтенда)
- [`goose`](https://github.com/pressly/goose) и [`sqlc`](https://sqlc.dev), если собираетесь работать с БД и запросами

### Запуск

```bash
git clone git@github.com:PKSonlem/myagentflow.git
cd myagentflow/backend

cp .env.example .env     # задайте свой API_TOKEN
make up                  # поднять Postgres
make run                 # запустить сервер
```

Проверка, что сервер запустился:

```bash
curl -i http://127.0.0.1:8980/healthz
```

Ожидаемый ответ: `HTTP/1.1 200 OK`.

На данный момент запускается каркас сервера. Приём событий, работа с БД и интерфейс ещё в разработке.

### Настройки

Все настройки задаются переменными окружения, значения для разработки есть в `backend/.env.example`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HTTP_ADDR` | `127.0.0.1:8980` | адрес сервера |
| `API_TOKEN` | `change-me` | токен доступа к API, замените на свой |
| `DATABASE_URL` | см. `.env.example` | подключение к Postgres |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `POSTGRES_PORT` | `agentflow`, `agentflow`, `agentflow`, `5432` | параметры контейнера с БД |

Сервер по умолчанию слушает только `127.0.0.1`. Не открывайте его в интернет: в событиях могут быть секреты из аргументов команд, а интерфейс рассчитан на локальное использование без логина.

### Полезные команды

Выполняются из каталога `backend/`.

| Команда | Что делает |
|---|---|
| `make up` / `make down` | поднять или остановить Postgres |
| `make run` | запустить сервер |
| `make test` | запустить тесты |
| `make generate` | сгенерировать серверный код из спецификации API |
| `make generate-ts` | сгенерировать типы для фронтенда |
| `make lint-api` | проверить спецификацию API линтером |
| `make migrate-up` / `make migrate-down` | применить или откатить миграции |

## Как подключить Claude Code

Эта часть появится вместе с приёмом событий. Идея такая: в `~/.claude/settings.json` для нужных событий добавляется http-хук, который шлёт payload на `http://127.0.0.1:8980/api/v1/hooks/claude`, а токен подставляется из переменной окружения. Хук отправляет событие и не ждёт ответа, поэтому агента он не замедляет, а остановка сервера не должна ломать сессию.
